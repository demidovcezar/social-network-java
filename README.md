# Social Network (Java)

A Java console application that models a small social network: users, friendships and communities. The code is split into layers (domain, repository, service, UI). Storage can be switched between a PostgreSQL database, text files and memory through a repository factory, without changing the rest of the code. Communities are found as connected components of the friendship graph.

## Features

- Add and remove users (the id is generated by the storage and shown after adding)
- Add and remove friendships (friendships are symmetric: Ana-Dan is the same as Dan-Ana)
- Removing a user also removes all of their friendships
- Count the number of communities (connected components of the friendship graph)
- Find the most sociable community (the connected component containing the longest simple path)
- Search users by first-name prefix, by last name, by both, or with a long last name
- Data is kept in a PostgreSQL database or in text files and survives restarts

## Architecture

The project follows a layered architecture:

| Layer | Package | Responsibility |
|---|---|---|
| UI | `UI` | Console menu (`Consola`); shows errors as messages |
| Service | `Service` | Business logic: users, friendships, communities, searches |
| Repository | `repository` | Storage (memory, text files, PostgreSQL via JDBC) and the factory |
| Domain | `domain` | `Utilizator`, `Prietenie`, `Pereche`, search criteria |
| Validation | `validators` | `Validator<T>` and the concrete validators |

## Persistence and configuration

The storage type is chosen in `src/main/resources/config.properties`. This file contains the real database password, so it is not in Git; copy `config.example.properties` (same folder) to `config.properties` and fill in your password:

```properties
repository.type=DATABASE      # DATABASE, FILE or MEMORY
utilizatori.file=data/utilizatori.txt
prietenii.file=data/prietenii.txt
db.url=jdbc:postgresql://localhost:5432/socialnetwork
db.user=postgres
db.password=YOUR_PASSWORD
```

| `repository.type` | Behavior |
|---|---|
| `DATABASE` | Data is stored in PostgreSQL (tables `users` and `friendships`) |
| `FILE` | Data is stored in text files and loaded at startup |
| `MEMORY` | Data lives only in memory and is lost when the application exits |

A missing or unknown value (for example `FILEE`) stops the application with a clear message.
Switching the storage type never requires changes in `Main` or in the factory.

### Database

Create the database `socialnetwork` and the tables:

```sql
CREATE TABLE users (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    first_name VARCHAR NOT NULL,
    last_name VARCHAR NOT NULL
);
CREATE TABLE friendships (
    id1 BIGINT,
    id2 BIGINT,
    friends_from TIMESTAMP NOT NULL,
    FOREIGN KEY (id1) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (id2) REFERENCES users(id) ON DELETE CASCADE,
    PRIMARY KEY (id1, id2),
    CHECK (id1 < id2)
);
```

- The repositories use JDBC: `Connection`, `PreparedStatement` and `ResultSet` are opened in try-with-resources.
- All queries use `PreparedStatement` with `?` parameters; values are never concatenated into the SQL text, so input such as `'); DROP TABLE users; --` is stored as plain text (no SQL injection).
- The user id is generated by the database (`IDENTITY`) and read back with `getGeneratedKeys()`. With `FILE` and `MEMORY` the repository generates it (greatest id + 1).
- `SQLException` is wrapped in `RepositoryException` with a specific message based on the SQL state (server not running, wrong password, missing database, violated constraint). The UI shows only the message, never a stack trace.
- The application connects on each operation, so it starts even if the server is stopped and continues once the server is started again.

### File formats

- `data/utilizatori.txt`: `id;firstName;lastName`
- `data/prietenii.txt`: `idUser1;idUser2;date` (date in ISO format, for example `2026-10-19T10:30`)

Files use UTF-8. If a file is missing, the application starts with an empty repository and creates the file on the first save.
An invalid line (missing field, bad number or date, failed validation, duplicate id) is skipped and reported with its line number; the rest of the file is still loaded.
`data/utilizatori_corupt.txt` is a sample file with corrupt lines.

## Design

- **Simple Factory**: `RepositoryFactory` is the only class that knows the concrete repositories; it picks one from a `Map<RepositoryType, Supplier<...>>`, so there is no `switch`.
- **Template Method**: `AbstractFileRepository` loads and saves the file; `UtilizatorFileRepository` and `PrietenieFileRepository` only convert a line to an entity and back. `InMemoryRepository` has a `genereazaId()` hook that the user repositories override to generate ids.
- **Strategy**: `Validator<T>` is injected into the repositories. It is a functional interface with a default `andThen` method, so validation rules can be written as lambdas and composed.
- **Dependency Inversion**: `Service` and `UI` depend only on the `Repository` interface, so the database storage was added without changing them.
- **Functional style (Java 8)**: `Repository.findAll(Predicate<E>)` with reusable criteria in static methods in `CriteriiUtilizator`, method references, `Optional`, and streams instead of loops in the service, the repositories and the UI.
- **Exceptions**: unchecked custom exceptions (`ValidationException`, `ServiceException`, `RepositoryException`) with exception chaining; they are handled in the UI.

## Requirements

- JDK 17 or newer
- PostgreSQL (only for `repository.type=DATABASE`)
- Gradle project; the PostgreSQL driver (`org.postgresql:postgresql:42.7.7`) is declared in `build.gradle.kts` and downloaded automatically

## Running

1. Open the project folder in IntelliJ IDEA as a Gradle project and let it sync.
2. Create `src/main/resources/config.properties` from `config.example.properties` (and the database, for `DATABASE`).
3. Run the `Main` class from the project root, so that the relative paths `data/...` and `src/main/resources/config.properties` resolve correctly.
4. Use the numbered menu.
